環境

本番（ステージング）

staging/

ステージング環境と本番環境はミラーの想定。MagicPodの「本番用ブランチ」で使用。

開発

develop/

機能追加済みの開発環境。MagicPodの「デフォルトブランチ（開発）」で使用。

パスは同一（index.html）なので、テスト設定のベースURLを …/branch-demo/staging/ と …/branch-demo/develop/ で切り替えるだけで環境を変更できます。

デモの流れ

  1. 準備：staging に対して購入フローのテストを作成（例：冷蔵庫を「カートに入れる」→ カートを開く →「レジに進む」→ お名前入力 →「注文を確定する」→「ご注文ありがとうございました」を確認）。
  2. 同じテストを develop のベースURLで実行 → ボタン名称が違うため失敗する。1本のテストで両環境を回せないことを示す。
  3. 現在の状態から本番用ブランチ（例：production）を作成し、staging のベースURLを使うテスト設定を紐づける。
  4. デフォルトブランチを開発ブランチとして扱い、develop のベースURLを使う設定にする。
  5. デフォルトブランチから機能ブランチ①（例：feature/button-rename）を作成し、「カートに追加」「購入手続きへ」に合わせてテストを修正 → develop で成功。
  6. デフォルトブランチから機能ブランチ②（例：feature/sale-banner）を作成し、お買い得バナーのテストを追加（バナー表示の確認 →「お買い得商品を見る」→ 見出し「お買い得商品」とセール品のみ表示を確認）→ develop で成功。
  7. ①②をデフォルトブランチへマージ → develop で全テスト成功。本番用ブランチは staging で引き続き成功し、開発の進行とテストのブランチが連動することを示す。

マージ時のコンフリクトを避けたい場合、機能ブランチ②は既存の購入フローのテストを編集せず、別のテストケースとして追加してください。
