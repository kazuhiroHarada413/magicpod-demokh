デモの流れ

  1. 準備：本番用ブランチ（staging）とデフォルトブランチ（develop）を用意。デフォルトブランチから feature/RenameButton と feature/offersBanner を作成する。
  2. Aさん：feature/RenameButton でボタン名称（カートに追加 / 購入手続きへ）に合わせてテストを修正 → feature-rename-button 環境で成功 → コードとテストをデフォルトブランチへマージ（コンフリクトなし）。
  3. Bさん：feature/offersBanner でバナーとセール価格のテストを追加 → feature-offers-banner 環境で成功。
  4. Bさんがデフォルトブランチへマージしようとすると、Aさんの変更と同じ商品カード部分を編集しているためコンフリクトが発生。マージ画面で両方の変更を残して解消する。
  5. マージ後のデフォルトブランチを develop で実行 → 成功。本番用ブランチは staging で引き続き成功する。

本来はデフォルトブランチの変更を取り込んだ状態で機能ブランチのテストを再実行するが、デモでは develop に全機能が入っているため、マージ後に develop で確認する形で省略する。
